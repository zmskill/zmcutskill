# 从文案、初剪、素材做出一条完整的口播成片

已经用三条真实口播走通过（横屏，中文，7 分钟以内）。照着做的时候，哪一步走不通、哪里和这里写的不一样，告诉用户，并按 `references/feedback.md` 记下来。

拿到的东西：一份文案（没有也行）、一条口播初剪（人已经剪好气口）、一个素材文件夹；要不要背景音乐由创作者定，要的话歌也由他挑。交回去的东西：一条能发的成片。好不好看由做的人负责；用户给的参考视频、镜头库、方法都是用来把片子做好的材料，**参考视频只取道理，不照抄画面，也不拿它当验收标准**。

## 0. 先读

本文 → `references/picture-and-words.md`（画面和话怎么对）→ `shot-library/index/koubo-fit.md`（每类句子配哪个镜头）→ `references/style.md`（样子从哪来）→ `references/sound-library.md`、`references/bgm.md` → `references/feedback.md`（用户的反馈怎么记）。

## 1. 摸清手里的东西

1. 初剪：时长、分辨率、帧率；每 20 秒抽一帧拼成一张图看人在画面里的位置、四周有没有黑边或拉伸带（有就在 `Shell` 的 `fit` 里放大一点推出去）。
2. 文字和时间，三步：
   - **听写**：`python3 scripts/transcribe.py <初剪.mp4> <项目文件夹>`，得到 `transcript.txt`（按停顿分的句子和起止秒）和 `tokens.json`（逐字时间）。用的是固定的 SenseVoice 离线模型，装在 `~/.cache/zm-talk-visual/asr`；还没装就照 `SKILL.md`《开工先体检》装（`python3 scripts/setup.py asr`，下载约 670 MB、装好占约 2.1 GB，先问用户）。不改用 AI 自带的转写：它给不出可靠的逐字时间，画面会对不准。
   - **断行**：把校对过的文案切成字幕稿，一行一条，存成 `字幕稿.txt`。照着 `transcript.txt` 里的停顿断：一行是一口气说完的一小句，不在词中间断；去掉标点；横屏一行要放得下（一般 6–14 个字）。这一步是做的人自己切，不用问用户。
   - **对时间**：`python3 scripts/align_script.py <项目文件夹>/tokens.json 字幕稿.txt subs.json`，得到每行字幕的起止秒，和每个字的秒数（`subs_chars.json`，画面用 `mkW(SUBS, CHARS)` 对到字）。它会报"文字一致率"，明显偏低（比如低于 0.9）就是文案和录音有出入；它还会逐处列出稿子里没在听写中对上的字，这几个字的时间是按前后猜的，看一眼是听写错了还是稿子改过。
   **没有文案时**：按 `transcript.txt` 自己断行，听写拿不准的字（同音字、软件名、英文）列出来一次问清，这是【停③】（见 `SKILL.md`《四个必须等用户回复的点》）。等他回之前可以先按最合理的猜测往下排表，但他没回不定稿；交付时列出改了哪几处、哪些是他确认的。
   **字以文案为准，时间以听写为准**；文案里的错字（比如"焚决"应为"焚诀"）问用户或对照他的素材改。
3. 素材：每张都打开看，拼成一张总览。逐张记下：图里是**谁**、是**哪件事**、有哪些能读的数字。文件名只是线索，不能当答案（曾经把一张和 A 的聊天截图配给了讲 B 的那句话）。
4. 音乐：每个文件看标签（哪首歌、多长），量性格，见 `bgm.md`。**不同文件不要假设是同一首。**
5. 音效库：在 skill 里，`assets/sfx-library/`。`音效库记录.json` 给程序读，`音效库记录.md` 给人看。来源和许可见那里的 README。
6. 背景音乐：先问要不要（不要就只留证据声和音效）。要的话，歌由创作者挑好给过来，skill 不挑歌；拿到后用 `scripts/bgm_analyze.py` 量速度和重拍（只打印；要存加 `--out`，存进项目的中间稿文件夹，别写进用户放素材的地方），再用 `scripts/bgm_prepare.py` 做配乐轨和 15 秒试听，做法见 `bgm.md`。

## 为什么用这几样工具

成片效果是在这套工具上调出来的。缺了就装，装不上就把路打通（见 `references/setup-help.md`），不换成别的。

| 工具 | 为什么是它 | 换了会怎样 |
|---|---|---|
| SenseVoice 离线听写（sherpa-onnx） | 中文准，给出**每个字**的起止时间；离线跑，不上传用户的口播，不花钱 | 画面要在说到某个字时出现，只有整句时间就对不准，会早一拍或晚一拍 |
| Remotion 4.0.484（版本锁在 `package-lock.json`） | 用代码写动效、逐帧渲染，同样的代码每次出来一样；镜头库和两套风格都是 Remotion 组件 | 换渲染工具，镜头库和风格要全部重写；换版本，动画细节可能变 |
| Remotion 自带的无头浏览器（chrome-headless-shell） | Remotion 官方推荐，版本固定，渲染结果稳定 | 用普通 Chrome，不同版本渲染出来可能不一样。环境里已经预装了同一种 chrome-headless-shell 的，可以直接用 |
| ffmpeg | 抽音频、混音、拼接、压片的通用工具 | 怎么装都行（brew、系统自带、pip 装的 imageio-ffmpeg），装出来是同一个工具 |

## 1.5 把 Remotion 项目跑起来

skill 里的 `remotion/` 只有代码，没有 `node_modules` 和 `public/`，也不往里装。下面说的 `remotion/` 都指工作区里那份（`setup.py remotion` 搭的，默认 `~/zm-work/zm-talk-visual/remotion`）：依赖、素材、片子代码都在那里，skill 文件夹保持干净。

1. **先体检**：`python3 scripts/doctor.py`，照 `SKILL.md`《开工先体检》做。有的不提、不重装；缺的问过用户后用 `python3 scripts/setup.py` 装。
2. 先确认环境是好的：`npx remotion still src/index.ts kshots out/kshots.jpg --frame=330`，出得了图就说明能渲染（`kshots` 不需要任何素材）。已经有无头浏览器时加 `--browser-executable=<路径>`（体检会列出路径）；`seg.sh` 等脚本会自己找。脚本没有执行权限就用 `bash xxx.sh` 跑。
3. 新片子的素材放进 `remotion/public/<片子名>/`：口播初剪叫 `src.mp4`，素材图按编号改成短名字。`Shell` 的 `video`、`Shot` 的 `src` 写的都是 `public` 里的路径。
4. 代码放 `remotion/projects/<片子名>/`：从选定风格的 `STYLE.md` 里写的模板复制过去（笔记本：`projects/_koubo-kit/` 的 `Kit.tsx`、`Notebook.tsx`、`KouboShots.tsx`；操作台：整个 `projects/_style-workbench/`，只改 `content.ts`；书桌：整个 `projects/_style-desk/`，大部分只改 `content.ts`，竖屏；高点要在项目里现做新的场，见第 4 步）。按内容新设计的，从零写外壳，镜头库的镜头照样能用：给新样子写一份 `styles/<名字>/values.ts`，外壳每帧调用 `useStyleValues`。每一段写完，在 `remotion/src/Root.tsx` 里 import 并照样加一行 `K('id', 组件, 帧数)`。没登记的 composition 渲染不出来。
5. 浏览器：用 Remotion 自带的无头浏览器（`setup.py browser` 装）；环境里已经预装了同一种 chrome-headless-shell 的（`CHROME` 环境变量或常见安装位置），`seg.sh` 等脚本会直接用。`seg.sh` 拼图要用 Python 的 Pillow。
6. `Root.tsx` 里登记了几个不需要素材的样片（`kshots`、`nbtest`、`workbench-demo`，书桌的 `desk1`、`desk2`）和一个写法示例 `example`。`example` 是照着改的模板，要先在 `public/demo/` 放一条 `src.mp4` 和一张 `shot.png` 才渲染得出来；确认环境用 `kshots`。新片子的各段自己加。
7. 系统里要有 `ffmpeg`（听写、混音、拼接都靠它）和 Python 的 numpy、Pillow、scipy，体检已经查过。ffmpeg 可以是 `pip install imageio-ffmpeg` 装的，脚本会自己找到；shell 脚本里用的是 `$FFMPEG`，没有就用系统的 `ffmpeg`。
8. **竖屏**：书桌风格（`_style-desk`）就是竖屏 1080×1920 的，竖屏口播优先看它合不合适。`_koubo-kit` 的布局（`Kit.tsx` 里的 `R_FULL`、`R_WIN`、`SideR`、`Shell`）是按横屏 1920×1080 写的；要用笔记本做竖屏，在 `Root.tsx` 里写 `K('id', 组件, 帧数, 1080, 1920)`，并且先把这几处改成竖屏的位置，做出第一段给用户看过再往下做。
9. **不同环境**：在 Linux 云端和 Cowork 的工作区里跑通过；Mac、Windows 的终端里还验证得少。哪一步报错，告诉用户，并记下怎么绕过去的。

## 2. 定样子

开工时问用户：这条的样子从哪来？① 按内容自己设计；② 从风格库（`styles/`）里挑；③ 照参考视频。**必须问，没有默认**；用户不答就停在这里等，第 1 步可以先做。三条路怎么走、风格卡怎么写，见 `references/style.md`。

**`_koubo-kit/Kit.tsx` 不是中性零件，它就是"笔记本"那套样子**（`styles/notebook`）。没选笔记本就不要直接复制它的外壳和颜色，否则每条都会长得一样。

不管走哪条路：不压暗、不加半透明黑幕；人物只做整幅等比缩放，不裁成大脸、不放大超过原片。做完写一张这条片子的风格卡，和代码放在一起。

人物放在哪由样子决定（笔记本：满屏 / 左边的窗 / 一排卡里的一张；操作台：在节目监视器里；书桌：在桌上的一部手机里，开头大、讲证据时当配角，高点可以拉到几乎满屏）。换状态的时刻对在换话题的地方。

## 3. 分段，排对照表

1. 按内容把全片切成段（开头、每个章节、结尾），每段几十秒。段的边界落在两句话之间的空隙里，记下每段的起点秒数和帧数；各段首尾相接，帧数加起来等于全片。
2. 每段排一张对照表，一行一句（或一小组）话：`时间 | 说的话 | 人物（满屏 / 窗）| 画面上配什么 | 镜头库 | 真素材 | 旋钮 | 高点`。"旋钮"写这一拍比上一拍拧了哪几个（主体、大小、来法、节奏、人、声），"高点"在高点的行写"★ 现做：……"。为什么要这两栏见 `picture-and-words.md`《主题不变，变奏不停》。
3. **"镜头库"一栏必须填**：先去 `shot-library/index/koubo-fit.md` 按句子类型查，写用了哪个镜头、取哪一段。表里有加粗英文名的是现成的口播版组件，直接用；只有镜头卡名字、还没有口播版的，要用就写"照卡现做：取卡里的哪个动作"，开做前读那张卡（`koubo-fit.md` 末尾有卡的路径），动作和参数照卡来；只是借个意思、不照卡做的，算"不用"。不用（包括人物满屏、只放真素材的行）就写"不用：……查过 xx、xx，为什么不合适"，**必须点名查过库里的哪个镜头**，只写"人物满屏""不合适"不算。用了镜头的行不到一半时，在表的末尾加一节"## 为什么这么少"写给用户看。排完跑：

   ```
   python3 scripts/check_mapping_table.py <对照表.md>
   ```

   不通过不许开始做画面。再跑一遍：

   ```
   python3 scripts/check_variety.py <对照表.md>
   ```

   它列出的"要看"逐条过一遍：是故意停住就在旋钮栏写"节奏：停住"，忘了变就改。
4. 排的时候问自己：这句话的画面是不是这句话的**证据或意思**，而不是装饰？只有字的画面不算画面；人物满屏旁边什么都没有，超过三四秒就闷。舞台上超过 1.5 秒什么都没有或只有一行小字，算空屏。
5. 真素材：整张给，只在说到的数字上画圈。裁到认不出是什么截图，就没有说服力。口播里没说的事实不往画面上加（年份、名字、别人的原话）；需要文字又不能编的地方用灰条代替。
6. 口播的数字和截图对不上时：字幕跟口播，画面用真截图，并告诉用户。
7. **【停①】把对照表发给用户，等他确认**。他只对样子、选歌这类事说过"你自己定"，也要发、要等他回一句。确认后在表末写"用户确认：<日期> <他的原话>"，再跑上面的检查。他明确说过全程直接做完的，照 `SKILL.md`《四个必须等用户回复的点》第 3 种做。

## 4. 搭画面

零件在 `remotion/projects/_koubo-kit/`，新片子复制一份到自己的项目文件夹再改：

- `Kit.tsx`：外壳 `Shell`（背景、人物缩放、章节标签、字幕）、舞台 `Stage`、白卡 `Card`、截图卡 `Shot`、满屏时两侧的卡 `SideL / SideR`、画圈 `Ring`、气泡 `Bubble`、弹出 `Pop`、上移出现 `Rise`、胶囊 `Pill`、小图标 `Ico`、关卡地图 `MapPanel / PitOpen / PitDone`。
- `Notebook.tsx`：录屏卡 `RecCard`、手画圈 `HRing`、章节路线图 `RouteMap / ChapterOpen`；人物演示录屏时用 `Shell` 的 `'mini'` 缩到左下角。样片：composition `nbtest`。
- `KouboShots.tsx`：镜头库里 8 个镜头的口播版：大数字环绕 `OrbitCounter`、一墙里挑 `PickWall`、私信墙 `DMWall`、场景硬切 `SceneCuts`、两句收尾 `TwoLines`、提问墙 `QuestionWall`、弯曲轮播 `CurvedReel`、书签 `BookmarkTap`。样片：`口播版镜头样片.mp4`。
- `Example.tsx`：一段长什么样。

做法：

1. 一段 = 一个文件 = 一个 composition，在 `src/Root.tsx` 里登记。
2. **时间不写死**。`const W = mkW(SUBS, CHARS)`（`CHARS` 是 `align_script.py` 出的 `subs_chars.json`），`W('字幕里的几个字')` 返回说到这几个字的真实秒数；不传 `CHARS` 只能按字在那一行里的位置估，会差零点几秒；元素写"说到哪个词时出现"。文案改了、重新对齐了，画面自动跟着走。
3. 边做边看：`projects/_koubo-kit/seg.sh <composition> <这段起点秒> <输出目录> <列数> 秒数…` 抽十几帧拼成一张图。看：字有没有超出卡片或画面、有没有互相压、有没有压住字幕和脸、舞台有没有空着、截图上的圈是不是圈在说到的那个数上。
4. **【停④】第一段代码写好、还没渲染时，用 `seg.sh` 抽 8–12 个关键时刻拼成一张图发给用户**：前面加 `SUBS=<subs.json>`，每格下面会标上全片时间和那一刻说的话，不用自己写标注。他说可以，再渲染这一段、做后面几段；后面每段也发关键帧图，他不用每段都回。
5. **高点现做**：对照表里标了 ★ 的行，为这条片子的素材新做一种场（新物件、新动作），不从模板和镜头库里原样拿。用了风格模板的，在自己项目的那份里加，不改 skill 里的模板。关键帧图里把高点那几格标出来，自己先看：最后一个高点是不是全片最大的。
6. 章节之间用同一个意象串起来会更整（比如一张关卡地图：主角走到坑边 → 跳过去 → 走向下一个）。意象从这条片子的内容里来，不要每条都用地图。
7. 做完如果觉得哪个现做的东西特别好、值得入库，问用户一句；没有就不记。

## 5. 渲染

- 渲染一段：`bash projects/_koubo-kit/rseg.sh <composition> <帧数> <输出目录>`。每段切成 330 帧一块，不带声音；已经渲染好的块会跳过，所以被单条命令的时长上限打断时，再跑同一条命令就会接着渲，直到输出目录的 `status` 里出现 `DONE`。
- 能留后台进程的环境（自己的终端）可以排队：`out/queue.txt` 里一行一个 `<composition> <帧数> <输出目录>`，后台跑 `projects/_koubo-kit/q.sh`。Cowork 这类环境里命令一结束后台进程就被停掉，不要用后台，照上一条一段一段跑。
- **渲染和抽帧不能同时跑**（内存会爆，渲染那一块直接失败）。`seg.sh` 会放锁，渲染脚本看到锁就等。
- 解码视频的缓存默认限在 800 MB（`rseg.sh`、`rchunk.sh` 的 `--offthreadvideo-cache-size-in-bytes`）：画面里同时放人和录屏时，不限会吃掉一半内存，渲染进程被系统杀掉。内存小的机器可以设 `OTV_CACHE=400000000` 再跑。
- 改了哪里只重渲染那几块：`rchunk.sh <composition> <总帧数> <输出目录> 块号…`。
- 每次打包会把整个 `public` 复制一份，脚本用完就删；和这条片子无关的素材别放在 `public` 里。
- 最后用 `python3 scripts/assemble.py --video 段1.mp4 段2.mp4 … --audio 混音.wav --out 成片.mp4` 出片：按顺序拼起来、x264（crf 默认 22）压一遍、声音两遍 loudnorm 压到 -16 LUFS、再量一遍成片，测量写在成片旁边的 `<成片名>_测量.json`。它打出"要看"就先处理。文件太大时（比如超过 150 兆）先问用户要不要压得更小（`--crf` 调大）。片尾最后一帧多定 2 秒让音乐自己收：画面里没做定格就加 `--hold 2`。不要自己另拼一套。

## 6. 声音

一张清单管全片（`scripts/sfx_mix.py` 读它）：人声、音乐分段、音效逐条。

- 音效：只在四种时刻配——讲的东西到了、有分量、换段、玩梗；一个动作一声；移动的过程和装饰不配。声音从音效库里按记录选，材质尽量和画面一致。详见 `sound-library.md`。
- 音乐（只在创作者要了、而且给了歌的时候）：说话时比人声低 17–20 dB，没人说话超过 1 秒才抬起来；说话下面不放带人声的歌；只在换章处换歌；证据声优先。详见 `bgm.md`。
- 有背景音乐时先跑 `python3 scripts/bgm_prepare.py <配乐表.json>`：截歌、每一刻跟着人声调音量、停顿处抬起来，出配乐轨、15 秒试听和画面要的频谱重拍。音效清单里音乐写 `{"文件": "配乐.wav", "已调好": true}`。
- **【停②】AI 听不到声音**：把试听发给用户，他说可以再铺全片；他说大了小了，就改配乐表里的数重跑。好不好听只能由他判断。

## 7. 审

1. 自己先过：每段的抽帧图。再把全片的关键帧按时间排成一长条看一遍：有没有一长段长得差不多的格子？
2. 起一个新的审片人（不知道你改过什么），只给成片、带时间的文案、必要的背景，照 `koubo-build-workflow.md`《盲审提示词》审，交回那张固定的表：八项分、总分、必须改、看了哪些、哪些没法看。表缺一项就让它补，不自己替它补。
3. 必须改的先改，改完**另起一个新的审片人审第二轮**（全片，不只看改的地方）。两轮的表都写进交付说明；没做第二轮要如实告诉用户。
4. 交的时候说清楚：做了什么、放在哪、哪里自己拿了主意、哪里不满意、需要他定什么。

## 8. 写回

用户说的每一句好和不好，按 `references/feedback.md` 记下原话，并且想清楚它背后的道理和下次要问自己的问题——**不要把它变成固定的数字和位置**。

## 走通时踩过的坑

- 一口气做完整版时跳过了查镜头库，后半段全是通用卡片，平。→ 对照表加了"镜头库"一栏和检查脚本。
- 素材配错了人。→ 第 1 步逐张记"图里是谁、哪件事"。
- 背景音乐拿错文件，25 秒处莫名换歌。→ 先看标签。
- 截图只截了头像和数字，没有说服力。→ 整张给。
- 把参考视频的画面和自己的放在一起比。→ 参考视频只取道理。
- 人物缩成窗以后右边空了 3 秒。→ 人物晚一点再缩，或者先给一张承接的卡。
- 印章、标签压住了正在说的那几个字。→ 抽帧时专门看。
