# 定样子：三条路和风格库

为什么要问：如果只有一套写死的样子，一开工就会把它套上去，每条片子都长得一样。

镜头库管**怎么动**（一墙里挑、大数字环绕、弯曲轮播……），样子管**长什么样**（外壳、颜色、字体、质感、动效性格、字幕、人放在哪）。三条路都要查镜头库，只有"定样子"这一步不一样。

## 开工时问

> 这条片子的样子从哪来？
> ① 我按这条的内容自己设计；② 从风格库里挑一套（附上推荐和样片截图）；③ 照你给的参考视频。

**必须问，没有默认**。用户不回答就停在这一步等，别的准备工作（听写、看素材、排对照表的文字部分）可以先做。用户已经说过的（比如开口就给了参考视频）不再问。

## ① 按内容设计

风格库里的"操作台"（`styles/workbench`）就是这条路做出来的。

1. **先找意象**：问自己，这条片子讲的事发生在什么地方、用什么东西做？讲配乐，配乐是在剪辑软件里做的，于是整条片子就是一个剪辑台；素材是笔记大纲图，于是是纸卡。这一步的意象可以带着这条片子的话题；入库时再按《风格卡取名》去掉话题，剪辑台入库叫"操作台"，纸卡入库叫"笔记本"。依据：界面隐喻，借观众熟悉的东西装新内容。
2. **检查意象装不装得下**：章节、人、每一类证据（截图、录屏、数字）在这个意象里有没有自然的位置？剪辑台里，人在节目监视器里，章节是时间线上的标记，证据是素材箱里的片段。有两样以上放不进去，就换意象。
3. **从意象往下推**：外壳长什么样、镜头怎么移动、章节怎么表示、颜色从素材和意象里取、字幕放哪。
4. **不能和上一条长得一样**：做完第一段，拿 `styles/` 里每套的样片看一眼。像哪一套，就回第 1 步。
5. **写成一张风格卡**（格式见下），和片子放在一起。用户满意了，问他要不要入库。

什么时候不适合硬找意象：内容很抽象（讲观点、讲心态），找不到对得上的东西。这时候宁可用干净的卡片样子，也不要套一个对不上的意象，否则会像在演戏。

## ② 从风格库里挑

1. 先看这条片子主要在做什么：讲经历、讲道理、演示操作、讲步骤、比数据、亮观点……
2. 到 `styles/README.md` 对每套风格的"适合"和"不适合"，推荐一两套，附上样片截图，让用户挑。只因为"都是讲 AI 的"这种表面相似就推荐，会选错。
3. 选定后读那套的 `STYLE.md`：颜色这些值、代码在哪、招牌动作、红线、哪些位置换成新内容。
4. 从代码开始改，不要照着文字描述重写，重写会走样。招牌动作（镜头怎么动、人放在哪、章节怎么表示）照代码保留；要换成别的软件界面这类"换皮"，只重画面板的外观。
   - 外壳的动作（比如操作台的镜头推拉、时间线）属于样子，不填对照表的"镜头库"一栏；那一栏照旧只写镜头库里的镜头。
5. 做完第一段，和这套的样片比：是不是同一套？哪里不像，就回去对照代码。

## ③ 照参考视频

1. **先问一句：喜欢它哪一点？** 整体感觉、某个镜头、配色，还是转场？看到喜欢的视频，人往往只喜欢其中一部分。用户不在时，先写下自己猜的是哪一点，再接着做，交付时说清楚。
2. 喜欢的是**某个镜头**：这不是样子的事，按镜头处理。拆出它的动作，用这条片子的样子重做；做得好就问要不要入镜头库。
3. 喜欢的是**样子**：只拆能搬过来的**关系**，不搬表面。
   - 能搬的：颜色和章节的关系、质感（亮还是暗、扁平还是有景深）、动效性格（干脆还是柔和）、意象的类型（播放器、笔记、软件……）。
   - 不搬的：它的版式、具体画面、它的颜色值本身。用户明确就要某个表面特征（"就要这个蓝"）时，照用户说的做。
   - 依据：类比迁移时，搬的是关系结构，不是表面属性。
4. 把拆出来的东西写成一张风格卡，后面照 ② 的第 3–5 步做。可以混着用，比如参考的质感加上用户自己的配色。
5. 做完不拿参考视频并排比，只对照拆出来的那张卡。

## 风格卡格式

每套风格一个文件夹 `styles/<英文名>/`，里面放 `STYLE.md` 和 `样片/`（3–5 张关键帧）。`STYLE.md` 写：

| 块 | 写什么 |
|---|---|
| 名字 | 按下面《风格卡取名》：标题写"意象名（用途）"，紧跟"给用户""给 AI"两句和 ID |
| 一句话意象 | 这套在模仿什么 |
| 适合 / 不适合 | 按"这段内容在做什么"写；还要写需要什么素材才撑得起来 |
| 值 | 颜色、字体、圆角、阴影、动效快慢：从代码里抄，标出代码位置；写明用户想换配色、字体改哪个文件 |
| 代码 | 外壳和零件在哪个文件、哪个组件；哪些写死了这条片子的内容，用的时候要换 |
| 招牌动作 | 这套之所以是这套的那几个做法 |
| 换内容的地方 | 新片子要往哪些位置填自己的东西 |
| 红线 | 不压暗、不加黑幕、人只做整幅缩放；再加这套自己的 |
| 用户怎么说 | 他的原话：喜欢哪里、否过什么 |

值只能记录颜色和字体，记录不了意象和构图，所以卡上必须同时有代码位置和样片。

## 风格卡取名

风格卡会给不同的创作者用，名字要同时让用户一眼知道什么时候选它，让 AI 知道什么时候用它。做法：像一个 Skill 有给机器的 ID、给用户的显示名"名字（用途）"、给 AI 的 description（做什么、什么时候用、什么时候不用）。

**1．每张风格卡写四样东西**

| 项 | 写给谁 | 写法 | 例子 |
|---|---|---|---|
| ID | 代码、文件夹 | 英文意象词，就是 `styles/` 下的文件夹名；定了不改 | `workbench` |
| 显示名 | 用户 | 意象名（用途） | 操作台（讲软件怎么用） |
| 给用户的一句话 | 用户 | 要讲……，手上有……，就选这个 | 要讲一个工具怎么用、一样东西怎么做出来，手上有录屏或界面截图，就选这个 |
| 给 AI 的描述 | 这个 skill 里的 AI | 做什么 + 什么时候用 + 什么时候不用 | 见 `styles/workbench/STYLE.md` 开头 |

**2．意象名怎么取**：一个地方或物件，2～4 个字的日常中文，听到就能想出画面。不带话题词（不写"AI""剪辑"），不用形容词（不写"科技风""高级感"），不用颜色（不写"深色……"），不用设计术语（不写"赛博""孟菲斯"）。

**3．括号里的用途怎么写**：写讲法，不写话题（写"讲软件怎么用"，不写"AI 赛道"）；用用户自己会说的话，越短越好。两套用途相同时括号可以一样，靠意象名区分。

**4．选风格看什么**：只看讲法和素材，不看话题。不建统一的讲法分类表，每张卡只写清自己适合、不适合什么。

**5．什么时候开新卡、什么时候合并**：
- 只是配色、字体、深浅不同的，是同一张卡的变体，不开新卡。
- 两套用途相同时，必须说得出用户在它们之间怎么选（比如想给观众什么感觉、手上有什么素材）。说得出就分开，两张卡的"给 AI"里都写明怎么二选一；说不出就合并。
- AI 判断不了该用哪套时，两套各做一小段（比如开头几秒）给用户选。

**6．名字和描述只写换了配色依然成立的东西**：意象、结构、招牌动作。配色、字体、深浅写在"值"一节，并写明用户想换时改哪个文件。

**7．什么时候取正式名**：刚做出来时用临时名，来源写在字段里，不写进名字；用户认可、入库时，再按这套规则起正式名。

## 入库

- 只有用户满意的才入库，和镜头入库一样：做完觉得这套样子好，问他一句；没有就不记。
- 入库时补齐风格卡的每一块，从成片里抽 3–5 张样片。
- 风格库只存做出来、被认可的样子，不预先写模板。
- **先拆"为什么好"，再写"长什么样"**：入库时逐场拆——每一场：哪句话、用什么证据、证据怎么摆、镜头怎么走、哪个字上做什么、配什么声——写进风格卡的《好在哪》；颜色、外壳放后面。
- **要拆成模板时，从原片代码改，不重写**。验收是"只填内容文件，把原片重做出来，同一秒对照看不出差别"，不是用假内容跑通（书桌模板就是这样验的：只填 `content.ts` 重做原片，抽 84 帧逐像素对上）。
- 风格卡写明**锁死的和要拧的**（见 `picture-and-words.md`《主题不变，变奏不停》）：只往模板里填内容，做出来会是模板的调调。

## 新做一套风格时怎么接进代码

- 写一份 `styles/<名字>/values.ts`（照 `styles/current.ts` 的 `StyleValues` 填），外壳每一帧开头调用 `useStyleValues(这套)`，镜头库的口播版镜头（`KouboShots.tsx`）就会跟着变颜色、字体和舞台大小。
- 镜头里画的小场景（夜晚、窗户这类插画）颜色不跟风格走，是故意的。
- 三条路里，① 和 ② 都在真实片子上走通过；③ 照参考视频还没在片子上试过，照着做时留意哪里不顺。
