# 口播成片：镜头库优先的做法

这份是做每一段时的细节：人物怎么放、怎么查、怎么盲审。总流程以 `koubo-full-film.md` 为准。

这份文件说的是"画面长什么样、怎么动、怎么接、怎么查"。一句话该不该有画面，看 `picture-and-words.md`。

## 四样材料各管什么

| 材料 | 管什么 | 不管什么 |
|---|---|---|
| 规则和元知识 | 这句话该不该有画面、强还是弱、怎么接、声音怎么配 | 不规定秒数、位置、次数 |
| 素材 | 有真东西就用真东西 | — |
| 镜头库 | 现成的镜头和配方；不够就用库里的零件现做 | 不是框，没有合适的不硬套 |
| 参考视频 | 只产出道理（"画面和话同时到""相邻画面有东西接着走"） | 不当目标样子，不当检查标准，做完不拿它来比 |

好不好看由做的人负责。用户的反应是信号，他不用说清为什么。

## 步骤

顺序和细节以 `koubo-full-film.md` 为准，这里是简版。

1. **对齐时间**。字幕稿对到每个字的时间，画面里所有时间都按"说到哪个词"去查，不手写。
2. **翻素材**。每张素材看清楚里面有什么字、什么数。关键数字的证据可能藏在一篇报道的正文里，不在标题上。
3. **定这条片子的样子**。先问用户样子从哪来（按内容设计 / 风格库 / 参考视频），必须问，见 `references/style.md`。按内容设计时先找意象：比如素材是笔记大纲图，就取纸卡（风格库里的"笔记本"）；讲配乐，就取剪辑台（风格库里的"操作台"）。不压暗画面。全片一套。
4. **看镜头库**。先查 `shot-library/index/koubo-fit.md`；要用的镜头，读它的卡片和代码。
5. **排对照表**。每句话一行：配不配画面、用哪个镜头的哪一段、换什么内容、用哪个素材、人物在哪、怎么接上一个、哪一层。给用户看过再做。
6. **做画面**。动作和参数照镜头卡，用库里的零件（`shot-library/kit/polish.tsx`：缓动、软阴影、颗粒）。
7. **配声音**。见下面。
8. **自查，再盲审**。见下面。
9. **一段一段做**。每段 20–30 秒，查完再做下一段。

## 人物怎么放

每次变化都是整幅画面等比缩放，不裁脸，不放大到超过原片。

- **满屏**：对着观众说话、提问、点名的句子。两侧可以有侧卡，卡不碰脸。
- **缩成一张卡**：连着摆几样证据时，人物自己变成那一排卡里的一张，摆完再变回来。
- **缩成窗**：旁边有一整块内容要看的时候。

选哪种，看这句话是"对你说"还是"给你看"，不看时间长短。

抠人（让东西走在人身后）只在开头用了一次。亮墙配白卡片时边缘看不出毛边。

## 声音

音效怎么选、怎么配见 [sound-library.md](sound-library.md)，背景音乐见 [bgm.md](bgm.md)。混音用 `scripts/sfx_mix.py` 读一张音效清单，不靠渲染器出声音，这样音量是算得出来的。

- 画面定了再配。
- 背景音乐先问要不要。要的话，说话时比人声低 17–20 dB，而且是每一刻都低这么多，不是整段平均；没人说话超过 1 秒才抬起来。细节以 [bgm.md](bgm.md) 为准。
- 成片整体 −16 LUFS 左右：用 `scripts/assemble.py` 出片，它会压好、在成片上量。
- 重音尽量放在句子之间；压在字上的要比人声低。

## 怎么查

**自己查，逐条过：**

- 画面和这句话对得上；素材是这句话的证据；数字和证据不打架。
- 没压暗，没黑板；人没比原片大，没裁脸；脸上没盖东西。
- 字幕没被挡；字看得清。手机横屏上读不出的小字，要么放大，要么删。
- 没有只出字的画面；该有画面的句子没空着。
- 全片一套样子；相邻画面有东西接着走。
- 数字落定后至少停半秒。
- 证据卡停着的时候，旁边不露出半张糊掉的脸。
- 后面要讲的内容，前面不提前亮出来。
- 有背景音乐时，说话处人声比音乐高 17–20 dB（每一刻都要，不是整段平均）；没有削波。
- 用了库里哪个镜头，和它自己的样片比，确认没做坏。

**盲审**：另起一个什么都不知道的审片人，只给它成片、口播原文和必要的背景，让它抽帧看、量声音、按七项打分并列问题清单。提示词见下面《盲审提示词》。实际用下来，每一轮都会抓到自查没看到的问题，一般要审几轮才到 8 分。

盲审的限度：它听不到声音，只能量；它不知道用户喜欢什么。它能挡住硬伤，不能代替用户看一眼。

## 盲审提示词（可以直接复用）

给审片人的只有：成片路径、带时间的口播原文、必要的背景（哪些是原片固有的、哪些素材作者手里没有、这一段后面接什么）。让它：

1. 全片每秒 2 帧过一遍；每个画面切换的时刻按每秒 15 帧看连续动作；挑 8 个左右关键时刻看原尺寸单帧。
2. 量整体响度和峰值，粗判音乐音效有没有盖过人声；如实说明自己听不到声音。
3. 按七项各打 1–10 分并写理由和时间点：画面和话对不对得上；有没有硬伤；好不好看；衔接和动效；节奏和吸引力；信息清晰度；声音。
4. 给总分（不是平均；8 分 = 可以直接发，7 分 = 还有必须改的），和按严重程度排序的问题清单，每条标"必须改"或"可改可不改"。
5. 没问题就直说没问题，不凑数，也不客气抬分。
6. **最后照这张表交回，一项不能少**（少一项就让它补，制作方不替它补）：

   ```
   | 项 | 分（1–10） | 理由和时间点 |
   |---|---|---|
   | 画面和话对不对得上 | | |
   | 有没有硬伤 | | |
   | 好不好看 | | |
   | 衔接和动效 | | |
   | 节奏和吸引力 | | |
   | 信息清晰度 | | |
   | 声音（只能量，听不到） | | |
   总分：__（不是平均）
   必须改：1. … 2. …（没有就写"无"）
   可改可不改：…
   这一轮看了什么：全片每秒几帧、哪些换场、哪些单帧、量了什么
   没法看的：比如听感、口型
   ```

七项的名字照抄，不换成别的。审两轮：第一轮审全片；必须改的改完，另起一个新的审片人再审全片一轮。

背景信息要给够。没告诉它原片自带的瑕疵、哪些卡是示意的，它会把这些都算成问题。

## 踩过的坑

- 把视频放进切成几十条的卡里，渲染会被撑爆。滑动的那十几帧改用预先抽好的图片。
- 一条命令里既切目录又删文件，会被安全检查拦下，整条命令都不执行。输出一律写到新目录。
- 分段渲染时声音会在接缝处断。画面分段渲染（不带声音），声音单独混，最后合。
- 原片最上面 12 像素是相机自己拉伸出来的一条，放大 1.2% 推出画面（这是某条原片的问题，换片子先看自己的原片有没有）。
- 截图里的字要按整行、按词的边界裁。


> 对照表每一行必须有一栏"镜头库"——写查过哪个镜头、用了哪一段，或者为什么不用。这一栏空着不许开始做画面。跳过这一步，后半段往往一个库里的镜头都没用上，画面偏平。
