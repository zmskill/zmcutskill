# 核心原则与第一遍做对

> 目标：换任何产品、换任何 BGM，第一遍就把片子做对、做顺、做好看。
> 当不同维度的要求发生冲突时，按下面「六件事」从上到下的顺序取舍：**上面的做对了能撑住全片，下面的永远给上面的让路**。其中运镜、转场与丝滑执行细节见 `references/motion-and-camera.md`。

---

## 一、做片的六件事（优先级从高到低）

### 1. 情绪对不对
音乐和画面靠情绪搭桥：两样东西给人同一种体感，才叫配。第一步永远先给音乐画像（`tools/zm_music.py`），得到**兴奋度、满空、明暗**三个维度，再推出画面参数：

| 音乐状态 | 画面跟着变 |
|---|---|
| 兴奋度高 | 动作快、幅度大、起得快落得干脆（加速约 6 帧，仍须有减速）、镜头短、卡拍硬切多 |
| 兴奋度低 | 动作慢、幅度小、曲线柔和、镜头长、切得少、飞得缓 |
| 满（乐器多、鼓密） | 画面丰富：层次多、同时在动的元素多、信息密 |
| 空（乐器稀疏） | 画面简洁：单主体、留白，但主体依然要大 |
| 明亮 | 浅底、通透、轻盈 |
| 低沉 | 深底、厚重、有光有影 |

- **音乐有多满，画面就要有多丰富。** 音乐最满的时候画面空着、摆着不动，是最常见的败笔。
- 情绪档位（内部分燃 / 中 / 松）由你根据用户随口描述、歌名/风格、产品气质自行定夺，不用术语问用户。

### 2. 讲清楚没有
真实痛点 → 魔法瞬间 → 一个证据 → 明确收尾（`references/story-and-copy.md`）。讲不清楚"解决什么痛、对我有什么用"，后面动效再炫也没有意义。

### 3. 画面自己好不好看
观众评判一段音画，首先看画面本身和声音本身的质量，"配不配"是在此之上的加减。**画面不好看，卡点救不回来。**
- **一个主意**：分镜前先提 3 个不同的视觉主意（各一句话 + 1 张定调静帧），选一个从产品自身生长出来、最有记忆点的贯穿全片。
- **有质感的统一**：保留并拉齐光影、景深、材质、层次与颗粒，不是把所有镜头剥成纯白/纯黑平涂。
- **主体够大**：一个时刻只让观众看一个主角并占住画面（量片底线：内容区域中位占比 ≥45%，不能连续 2 秒低于 25%）。
- **开头 2 秒**：必须有大主体在动、立住悬念，拒绝小框小字慢吞吞淡入。
- **力气用在两处**：观众记住的是最高潮（魔法瞬间）和结尾（品牌落版），这两处做到最好。

### 4. 同步点：少数几下，做到准、做到重
"卡点感"来自**少数几个被明确感知的同步点**，而不是每帧硬凑拍子。
- 数量按音乐画像给出（燃每 30 秒 6–12 个，中 4–8 个，松 2–5 个），钉在音乐炸开、最强重拍与小节首拍上。
- 每个同步点按经典动画表演法则做足四件事：
  - **预备（Anticipation）**：之前反向微收、或画面慢下来/暗一点；
  - **夸张（Exaggeration）**：幅度比"合理"更大；一帧事件（硬切、换词、数字跳）直接落拍，位移/缩放必须让速度最快的一刻过拍、前后带加减速（绝不 1–3 帧弹出定住）；
  - **跟随（Follow-through）**：落定后保留余波、微晃或光晕荡开；
  - **重音 + 让开**：配一个有分量的声音对准 `hitF`，音乐在同步点上短时 `duck()` 让开。
- 其余非同步点动作不硬凑拍子（差 2–3 帧的半对不对最难受）。
- **屏住一拍**：全片最大爆发前留半拍到一拍蓄力（画面变慢、微暗，镜头仍极慢推进，绝不冻帧）；歌自带停顿就顺着用，歌在冲刺过门就不掐音乐、只在画面上屏住。

### 5. 流动：先看关系，再立规律、超额兑现
- 两个画面的关系决定接法：延续 → 空间飞过去；同物换角 → 同物接续；换话题要劲 → 速度接力卡拍硬切。
- **视线落点连贯**：切之前观众看哪，切之后新焦点就在哪。
- **切点藏在运动里**：静止切静止就是翻页 PPT。一次只变必要属性，不要位移、旋转、变色、模糊一起乱变。
- **惊艳感来自"打破预期"**：先立一个规律（同动作重复 2–3 次），屏住，再给出超出预期的结果（通常是魔法瞬间）。

### 6. 其余工程细节
零件挑选、素材采集、音效配置、两道关口见各专项文档，均服从以上五条。

## 二、第一遍就做对：高频冲突统一与底层工程原理

以下规则整合了多轮实战返工教训与浏览器渲染/影视剪辑通用底层原理，**写方案前、写代码前各核对一遍**。

### 1. 音乐满段的「三层动法」（解决动感、克制与读字冲突）

| 层级 | 做什么 | 是否对拍 | 数量约束 |
|---|---|---|---|
| 底层：镜头 | 在 3D `World` 空间里连续飞行；读字时仍保持微推（`drift`），永不死停 | 不对拍 | 全程；音乐满段任意 0.7 秒内整屏须有变化 |
| 中层：元素 | 进场、框选、点亮、换词、点击（位移/缩放必有加减速鼓包） | 对拍 | 按档位达到每小节画面事件数 |
| 顶层：整屏特效 | 整屏缩放泵、曝光闪（`punch`）、震屏、色散 | 钉在最大同步点 | **全片 ≤3 处，两处间隔 ≥16 拍**（卡拍硬切、镜头飞镜不计入此限） |

- 禁止镜头逐拍来回推拉（看起来像画面跟着鼓点发抖）。
- 禁止一张静态截图摆着、只有小框或光标在动超过 1.5 秒。

### 2. 构图、光学克制与浏览器 3D 渲染清晰度
- **主体不够大时，改裁切排版与机位推近，禁止给整个镜头/零件套外层 `scale`**：外层硬放大极易把卡片、文案推出画框裁切；改完须逐帧检查边缘。
- **不为了拉高内容占比把后续元素提前露出来**：例如品牌落版，最后落定的那个元素应是唯一的新焦点。
- **3D 透视下 UI 防发糊（浏览器光栅化原理）**：CSS 3D 变换对小尺寸 DOM 放大极易子像素发糊。真实产品界面一律按 2x 原生尺寸截图作为高清贴图，在 3D 平面上缩小或 1:1 渲染；出现文字发糊先查贴图分辨率链路。
- **镜头与特效克制**：软件产品宣传片默认不加手持抖动；高光/扫光特效一个镜头只给主角一次，且必须严格裁在元素圆角边界内（`overflow: hidden`）；飞入页面的 UI 元素必须落进布局真实槽位，不悬浮在界面上方。
- **机位服务可读性**：信息密集的页面/报告正视或小倾角展示，大面积风格化倾斜必须确认文字清晰度。
- **确定性渲染（Remotion 基础原则）**：严禁使用 `Math.random()`、`Date.now()` 或依赖异步未就绪资源，所有随机值用带种子的确定性函数（`assets/lib/helpers/rand.ts`），图片用 Remotion `<Img>` 等待加载完成，保证相同帧号任意次渲染逐像素一致。

### 3. 内容真实性与文字可读性
- **每句话必有实测依据**：写入设计 spec 的 `## 片中说的每句话`。没实测做成的功能绝不演成做成了；实测只跑了一次的数据明确说是一次。
- **真实产品界面一律用实机截图抠图**：不手画假界面，不用 `▭ ◈ §` 等符号顶替图标；确实需要演示用的虚构数据/文档，排版必须完整饱满。
- **广播级有效像素字高**：要被观众读懂的字幕有效字高按成片像素 ≥56px（1080p 约 5% 帧高），辅助信息 ≥32px，绝不按未缩放前的 CSS `fontSize` 估算。全片大字字重统一。
- **防挤字与防裁切**：替换文案（尤其含中英文混排）后用 `measureText` 或实际渲染核对行宽；关键句必须整句完整居中停住至少 0.5 秒（期间镜头慢推，不冻帧）。
- **字幕避让**：排镜时预留字幕安全区，不压主体内容、不白字压浅底，上一句完全退出后再出下一句；若镜头大幅推近或弹卡片会遮挡字幕，宁可不加字幕。

### 4. 声音底线与改片联动表
- 每个音效音量一律用 `tools/zm_sfx_levels.py` 计算，不拍脑袋手填。
- 成片（带 BGM 与不带 BGM 两版）一律过 `ffmpeg loudnorm=I=-14:TP=-1.5:LRA=11` 响度标准化后再量片。
- 音乐让开（`duck`）只在同步点触发；普通音效被盖住时换不同频段的音色，不滥用让开。
- 量片没通过绝不送独立终检；改完片子同步更新设计 spec 总谱与《没做清单》。

**改一处之前，先查会碰到谁：**

| 准备改什么 | 动之前先核对 |
|---|---|
| 让画面动起来 | 是否变成了逐拍抖动？整屏特效是否超 3 处？ |
| 让镜头少动 | 是否又出现连续静止超过 1.5 秒的段落？ |
| 放大主体 | 是否把元素或文字挤出画框？是否撞到字幕？ |
| 加字 / 加字幕 | 是否遮挡主体？按字数 ÷ 6 秒读得完吗？ |
| 加音效 / 提音量 | 是否破音？同时响是否超过 2.5 层？是否滥用让开？ |
| 调时间线 | 零件主落点与切点还在拍上吗？总谱与音效表同步改了吗？ |

## 三、往上做：从"没毛病"到"惊艳"

量片全过只代表没有硬伤。每次交付还要主动检查三件事：
1. **魔法瞬间必须清晰且有爆发层次**：到位那一帧不能是一团运动模糊，到位清晰后留极短呼吸，再接更大的动作展开。
2. **落版克制有力**：品牌名足够大（标志+名称至少占画宽 1/3），最后落定的一下是画面唯一新变化。
3. **至少一处意料之外**：定调时的三个主意里，优先选别人没这么做过的表达方式。
