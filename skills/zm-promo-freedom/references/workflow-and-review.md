# 制作流程、三道查、两道关口与独立终检

> 同一个问题，在纸上改一行字只需几秒，在小样阶段改只需几分钟，到全尺寸成片终检后才发现要返工一小时。
> **核心策略：问题前移、三道拦截、第一遍就做对；不为省时间降低终检标准。**

---

## 一、开工一次问清与两种协作模式

开工时把用户答得上来的事**一次性问完**（用大白话，不甩术语）：
1. 做哪个产品、聚焦单个功能还是介绍全产品？是否需要用户先登录账号或协助跑一次实测？
2. 用哪一首有授权的歌、大致想做多长？（用户没有歌时，把 `assets/audio/bgm/去哪找歌.md` 里的正规平台发给他挑，顺便听一句他想要的大致感觉。）
3. 片子准备发在哪？有没有品牌禁忌或不能说的话？
4. **协作方式**（若用户还没提前说明，必问）：「你是想让我**一路全自动做完直接交片**，还是在**痛点故事、3 张效果图拼图、整片画面与节奏时间表**这三步先给你确认再往下做？」

- **全自动模式**：用户选了全自动（或明确说"你全权决定"），问清以上信息后不再反复打扰，连续推进至独立终检通过并交片。
- **共同创作模式**：用户选了一步步确认，只在 **① 痛点与故事简报 → ② 3 张效果图拼图（内部对应：三个视觉主意与定调静帧）→ ③ 整片画面与节奏时间表（内部对应：过关口一后的完整分镜总谱）** 三个关键节点暂停等用户确认；采集细节、代码参数、SFX 钉帧与技术质检仍由你自主完成。跟用户确认时一律用大白话描述，不直接抛术语；用户中途说"你全权决定"即切回全自动。
- 每一步记录起止时间，交片时写入《没做清单》的 `## 用时`，便于看清耗时瓶颈（记用时不是为了赶工降标）。

## 二、三道查与两道脚本关口

### 第一道：纸上检查 → 关口一（写正式镜头代码前必过）

定调静帧可先渲染；**正式镜头代码必须等关口一通过后才开始写**。运行：

```bash
python3 $SKILL/tools/zm_check.py plan <设计spec.md> \
  --profile analysis/music_profile.json \
  --styleframe out/qa/styleframes.jpg \
  --fit analysis/fit_parts.md \
  --phase analysis/beat_phase.md
```

设计 spec 必须包含以下二级标题（标题文字照写，供脚本校验）：

| 标题 | 必须写清的内容 |
|---|---|
| `## 真实吐槽` | ≥3 条真实用户原话，每条带出处（链接或 `出处：…`） |
| `## 选中的痛点` | 打分胜出的唯一痛点与钩子具体时刻 |
| `## 魔法瞬间` | 全片唯一的高潮瞬间 |
| `## 证据` | 一个实测数字或前后对比，注明哪次真实使用（未实测写明原因） |
| `## 全片骨架` | `zm-single-feature-five-beats` 或 `zm-promo-energy-arc`，标明 `片长：NN 秒` 与各段小节数 |
| `## 音乐画像` | `zm_music.py` 结构表、情绪档位与判断依据（`--feel`）；安静段超限已剪歌；附 `--phase` 校验通过 |
| `## 一个主意` | 3 个不同视觉方向各一句话 + 选定方向与理由；附 `--styleframe` 拼图 |
| `## 全片一套皮` | 底色（≤2 种，注明切换点）、字体、主色、强调色、光影质感 |
| `## 成果特写` | 哪一镜、哪份真实成果、占比（≥60%）、可读秒数（≥1 秒） |
| `## 镜头路线` | 全片 2–4 段连续 3D 空间布局与镜头飞行顺序 |
| `## 每段的展示手法` | 各段展示手法，同一种不重复出现 |
| `## 功能到镜头` | 表格含「首选」「备选」「秒」「底色」列；30 秒 ≥8 个小零件、单镜 ≤6 秒、同源 ≤1/3；现写行注明 `看过：零件甲、零件乙` 与原因 |
| `## 用到的零件和落点` | 每首选零件一行：零件名 + 零件卡落点帧号（标出主落点）；附 `--fit` 文件 |
| `## 看过的样片图` | 已打开查看 `preview-sheet.jpg` 的首选与备选零件名 |
| `## 镜头怎么接` | 每缝一行：`上一镜 → 下一镜｜关系：…｜锚点：…｜接法：飞过去 / 卡拍硬切 / 同物接续 / 糊着换｜落在第几拍`（糊着换 ≤1，飞过去与卡拍硬切都要有） |
| `## 总谱` | 九列表：小节/拍/帧/音乐/画面事件/镜头零件/接/音效/同时几层；含 `魔法瞬间`、足量 `★同步点`（均配音效）、至少一段 `连打`、同时 ≤2.5 层 |
| `## 片中说的每句话` | 三列表：`这句话｜出现在哪｜依据`，所有大字/字幕/行动句均有实测依据 |
| `## 只读大字` | 按顺序连写全片大字，单独通读故事完整 |
| `## 脚本关口` | `story-and-copy.md` 第四节 8 条逐条写「过 / 不过」 |

关口一通过后会在 spec 同目录生成 `.关口一通过.json` 记录。

---

### 第二道：半尺寸小样检查（不请独立终检）

写完代码先渲半尺寸带音小样：

```bash
npx remotion render src/index.ts <合成名> ../out/draft.mp4 --scale=0.5 --crf=30
```

1. 对小样跑 `tools/zm_film_check.py`，报告存为 `reviews/小样量片.md`，改到 `**通过。**`；
2. 导出 0.1s/帧缩略图与每秒 2 帧总览拼图，按下面「画面先查八条」和零件样片图逐镜自查演示残留、穿帮、字遮挡与顿挫；
3. 局部改动只用 `--frames=起-止` 局部重渲验证，确认全部无误后再渲全尺寸。

---

### 第三道：全尺寸成片 → 量片 → 独立终检 → 关口二交片

全尺寸整条只渲一次（同步导出带/不带 BGM 两版并过 `loudnorm`），先跑正式量片 `reviews/量片报告.md`（必须通过且晚于成片），再送独立终检。

#### 独立终检协议（审到"可以交付"为止，不设轮数上限）
- **每一轮必须派全新的独立审片人**（新开无上下文 subagent，既不带做片记录，也不沿用上一轮审片人）。任务说明存为 `reviews/终检任务说明.md`。
- **先盲看成片写「第一眼」**：先**只给成片**（不给 spec 和清单），让审片人看完整片并写下三句话：看完记得住什么？有没有贯穿全片的主意？最强一刻够不够强、有没有"没想到"的地方？说不出来 = 片子只是"没毛病"，直接列为必须改第一条。
- **再查「`## 画面先查`」八条**（每秒 2 帧总览图 + 0.1s/帧细节图逐条判「过 / 不过 + 秒数」，不过一律算必须改）：
  - **0. 第一眼**：记忆点、主意与惊喜感；
  - **1. 慢放与顿挫**：有无明显发软/冻帧/连续 >1.5 秒死停（核对代码无 `holds`/`fitPart`）；
  - **2. 一套皮**：各镜拼排，底色 ≤2 种且只换 1 次、字体样式与光影质感是否统一；
  - **3. 成果特写**：有无至少 1 镜真实成果占屏 ≥60%、可读 ≥1 秒、文字清楚；
  - **4. 演示残留**：逐镜对照零件样片图，有无未换干净的图标/头像/贴纸/示例文案；
  - **5. 黑边坏帧**：有无黑边、露底、花屏、元素被画框裁切或字幕被挡；
  - **6. 音乐和画面**：量片报告是否通过；抽 5 行总谱核对当帧画面是否真发生；满段有无摆着不动；魔法瞬间是否钉在炸开处；
  - **7. 接缝**：换镜是否踩在音乐变化处、是否藏在运动里（禁静止切静止）、糊着换是否 ≤1 次。
- **单独核查四项核心体验**（逐一写结论）：
  - **转场**：逐接缝看前后各 6 帧，是否属飞过去 / 速度接力硬切 / 同物接续，糊着换 >1 = 必须改；
  - **卡点**：同步点当帧是速度最快刻或干脆切点，还是弹出定住/软落定？有无等间隔连打段？
  - **运镜**：是否在纵深 3D 空间连续飞行、有无急停急起、高速处运动模糊是否开启、屏内是否都在播？
  - **丝滑**：按 0.1s/帧及卡点前后 10 帧逐帧查，有无 1–3 帧弹出定住、突然刹停、零件中途冻住或切点速度断档？有一处明显顿挫 = 必须改。
  - **补充技术项**：同种展示手法是否重复、音效是否单音用到底、有无真实隐私信息泄露、音画同步与响度是否达标。
- **问题分级与修改闭环**：一次把问题提完，分**「必须改」**和**「建议」**。改之前先写 `reviews/修改计划.md`（写清每条改法及按 `core-principles.md` 联动表会碰到谁），受影响段落先渲小样验证、过量片，再出新版成片交给全新审片人复核。

#### 关口二：交片前强校验

交付前在设计 spec 补全 `## 读过的文档`（逐份如实写「全文」或「部分 + 原因」，核心文档必须读全文），准备《没做清单》（必须含 `## 演示残留`、`## 用时`、`## 终检提的问题，各是哪一步该做对的` 归因表，如实列出一切简化、未实测项或风险），然后运行关口二：

```bash
python3 $SKILL/tools/zm_check.py deliver <设计spec.md> \
  --video out/promo.mp4 \
  --review reviews/终检报告.md \
  --notdone reviews/没做清单.md \
  --filmcheck reviews/量片报告.md \
  --draftcheck reviews/小样量片.md \
  --project video/src
```

关口二全部通过后，将成片（带/不带 BGM 两版）、音效试听页（`reviews/音效试听.html`）、量片报告、终检报告与《没做清单》一并交付用户，并在回复开头主动说明《没做清单》里最要紧的事项。
