# 视觉统一、成果特写与小零件镜头库

> 视觉语言必须从目标产品自身生长出来。小零件只借动作语法，**皮肤、内容、品牌与光影质感必须全部统一成这条片子自己的样子**。

---

## 一、一个主意与定调静帧

分镜前必须先提出 **3 个不同的视觉主意**（写入 `## 一个主意`：各用一句话说清创意，写明选了哪一个、为什么），并先渲染 **3 张定调静帧**（问题段、魔法瞬间、落版）拼成一张图（`out/qa/styleframes.jpg`）：
- 三张摆在一起看，必须一眼像同一条片子；
- 共同创作模式下请用户挑选，全自动模式下自主定夺并写清理由；
- 关口一（`--styleframe`）强制检查静帧文件存在，绝不事后用成片截图补交。

---

## 二、全片一套皮、成果特写、主体占比与演示残留

### 1. 全片一套皮（写入 `## 全片一套皮`）
- **底色**：最多两种基调（一明一暗），写明色值与层次（渐变、光斑、景深虚影、颗粒，非纯白纯黑平涂）。全片只在**一个地方**切换底色（通常是魔法瞬间：问题段暗 → 登场后亮，或反过来），写清切换位置。
- **字体**：1 种中文字体 + 1 种西文/数字字体，写明字重；全片大字统一样式（不要这里描边、那里发光、另一处纯色）。可用 `remotion/public/library/fonts/` 里的 10 款 SIL OFL 1.1 中文字体。
- **主色与强调色**：各 1 个，取自目标产品界面或品牌；强调色只给每句大字里最关键的词。
- **质感拉齐**：保留并拉齐原零件优秀的光向、景深、圆角、阴影与颗粒数值；浅底零件迁入深底段（或反之）时，文字与阴影必须同步反色适配。
- 设计 spec 的 `## 功能到镜头` 表格中，每行标明该镜底色（明 / 暗）。

### 2. 真实成果特写（写入 `## 成果特写`）
魔法瞬间之后，**至少有一个镜头让产品真实产出占画面 60% 以上，并保持可读至少 1 秒**（1080p 下正文有效字高 ≥28px）：
- 必须是真实使用拿到的截图、导出页或高清画面，不能只用代码画示意，也不能只用小缩略图或斜飞总览糊弄；
- 优先放在歌收住的小节；若在音乐满段展示，用慢推、页内滚动、逐拍框选点亮保持画面活跃（"停 1 秒"指该成果持续在场可读，不是画面死停）；
- spec 里写清：哪一镜、哪份真实成果、占比百分比（≥60%）、可读秒数。

### 3. 主体占比与开头 2 秒
- **主体够大**：主角的宽或高至少占画面一半；小界面（手机、输入框、按钮）直接推近特写，周围用光影和虚景托底而不抢戏；落版标志+产品名总宽至少占画宽 1/3。量片底线：内容区中位占比 ≥45%，低于 25% 的时长 ≤10% 且不连着 2 秒。
- **开头 2 秒**：第一眼就要有大主体在动（撑满屏幕的字、冲到眼前的物体或正在发生的混乱），从 21 个"钩子"零件里看样片图挑选首帧就有冲击力的。

### 4. 清除演示残留
零件里原本的界面、文案、头像、海报、贴纸、图标、示例品牌名全是演示内容，必须全部替换成目标产品内容。交片前逐镜对照 `preview-sheet.jpg`，核查是否还有残留或黑边露底，将结果写入《没做清单》的 `## 演示残留`（没有就写"逐镜头对照过，没有"）。

## 三、238 个小零件镜头库用法

本 Skill 选镜头一律从 **238 个小零件**中选（1 个零件 = 1 个独立动作，1–6 秒），按用途分为 **12 类**（痛点、钩子、输入、点击确认、结果登场、功能演示、证据、列举、字卡、转场、过渡动作、品牌落版）。

| 资源 | 路径 | 用途 |
|---|---|---|
| 零件总表（先读全文） | `references/parts-own/INDEX.md` | 12 类速览，一次读完 |
| 零件卡 | `references/parts-own/<零件名>.md` | 帧范围、落点、进出衔接 |
| 样片与 12 格抽帧图 | `demos-own/parts/<零件名>/`（`preview.mp4`、`preview-sheet.jpg`） | 选镜前必看样片图，不凭名字猜 |
| 机器索引与落点数据 | `gallery/api/parts-own.json`、`gallery/api/parts-landings.json` | 校验时长与落点帧号 |
| 原镜头参考 | `references/shots-own/`、`references/groups-own/`、`demos-own/<类>/` | **不直接选**，仅在选中零件换内容时查阅"怎么换内容"和"已知坑" |

### 选零件六条规则
1. **先算合拍**：选镜前跑 `python3 $SKILL/tools/zm_fit_parts.py --bpm <BPM> --mood <档位> --use <用途>` 并保存至 `analysis/fit_parts.md`。
2. **十二类都要扫过、样片图必须打开看**：首选和备选的 `preview-sheet.jpg` 都要看过并记进 `## 看过的样片图`。
3. **数量与时长**：一拍一个零件；单个镜头 **≤6 秒**（必须更长如连续实操录屏须写 `理由：…`）；**30 秒至少 8 个小零件**（按片长同比例，最少 4 个；产品实录截图镜头另算，但不能全片靠录屏和现写撑）。
4. **不重复、不扎堆**：同一种核心动作全片只当一次主角；同一个原镜头拆出来的零件可以连续衔接，但总时长不超过全片 1/3。
5. **确需现写须说明原因**：库里确实没有合适动作才现写，在 `## 功能到镜头` 该行写明 `现写（看过：零件甲、零件乙，原因：…）`（至少列出 2 个真实零件名）。
6. **把落点抄进 spec**：在 `## 用到的零件和落点` 中一行写一个首选零件的名字 + 零件卡里的落点帧号，并标出主落点。

### 把零件用到片子里的正确方式
1. 读完整份零件卡 + 原镜头卡的"怎么换内容/已知坑" + 原镜头代码对应帧段。
2. **整段搬**（推荐）：把原镜头文件复制到片子工程 `video/src/`，替换文字、配色、图片为目标产品内容，再用 `PartPlay`（`assets/lib/helpers/partPlay.tsx`）只播该零件的 `from`–`to` 帧段；**照着重写**：保留原缓动曲线和时长配比，用目标产品真截图重构画面。
3. **代码画的 UI 面板直接替换成真实产品截图**：把原演示卡片/界面框整块换成目标产品的高清 2x 截图或动态页面，动作、运镜和时间不变，不要因为原样例是代码画的就放弃好动作。
4. **一口气按原速播完，严禁冻帧和慢放**：
   - `PartPlay` 只传 `from` / `to`，**绝不传 `holds`，禁用 `fitPart`**；
   - 对拍靠挪起点：`起点帧 = onF(拍号) − (落点帧 − 零件起始帧)`（每零件只对一个主落点）；
   - 需要多看一会儿时，零件播完停稳后靠镜头 `drift` 慢推延续阅读（最多多出 1 秒左右）；时间仍不够就加一个零件，不拉长原零件。
5. **依赖复制**：用到的共享代码件从 `$SKILL/assets/lib/helpers/` 复制进 `video/src/lib/helpers/`（`world.tsx`、`partPlay.tsx`、`mix.ts`、`polish.tsx`、`groupClock.ts`、`beatLand.ts`、`plane.ts`、`rand.ts`）；占位与字体素材已在 `remotion/public/library/` 和 `remotion/public/textures/`（用 `new_video.py` 建工程时会自动带入 `video/public/`），实做时优先替换为目标产品自己的真实图片。
